# Planning trail

Written before the build, in order. Each phase builds on the previous one.
They're kept as they were written, as a record of what was planned and why;
results are added in place (for example, the spike results in Phase 6).

| Phase | What it settles |
|---|---|
| [1. Problem brief](phase-1-problem-brief.md) | The problem, who it's for, success metrics, non-goals |
| [2. Requirements and constraints](phase-2-requirements-constraints.md) | The core scenario, requirements, must / should / could, constraints |
| [3. Domain model](phase-3-domain-model.md) | The terms, the span trees per source, the invariants |
| [4. Flows and failures](phase-4-flows-failures.md) | Each flow step by step, and what happens when each step fails |
| [5. Architecture and decisions](phase-5-architecture-decisions.md) | The ADRs: each decision, its alternatives and consequences |
| [6. Risks and skeleton](phase-6-risks-skeleton.md) | The riskiest assumptions, tested with spikes before building |
| [7. Slices and plan](phase-7-slices-plan.md) | The work cut into vertical slices, with a fallback decided in advance |

The attribute mapping every source follows is in
[`../conventions.md`](../conventions.md).
